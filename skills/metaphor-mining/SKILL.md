# Metaphor Mining

- id: `metaphor-mining`
- family: semantic transfer
- status: draft
- implementation: complete editorial procedure; independent acceptance pending
- requires: research-required for factual source properties
- outputs: candidate ledger, method artifact, feedback/state delta

## Mechanism and boundary

Map a property from another domain onto the brand promise, then select its name-bearing object/process. The artifact pairs useful and misleading transfers. Unlike `lexical-research`, retrieval is not enough: the target relation is an explicit analogy and need not be an established lexical sense.

## Use, avoid and inputs

Use for a promise that benefits from imagery and emotional distance from the category. Avoid decorative exoticism, metaphors contradicting the offer or properties requiring a fabricated scientific story.

Required: one credible target promise and one unacceptable implication. Default: three property-level directions and 6–12 universe previews if navigation is open. Optional: desired familiarity, narrative length and direct-word versus transformed output. A full metaphor is “brand is like X because Y,” not just a mood label.

## Procedure

1. State target promise without metaphor. List transferable properties (e.g. temporary, responsive, interwoven) and exclusions.
2. Propose disparate worlds, with provisional words and evidence labels. Select one world, not twelve simultaneous research projects.
3. Verify two relevant source properties when possible. For each object create two columns: useful transfer and misleading transfer. Record where the analogy stops.
4. Generate direct unchanged forms first. If spelling transformation helps, create a child branch with an exact operator rather than hiding it inside metaphor.
5. Compare a close analogy, a surprising analogy and one tempting but misleading case in identical product introductions. Ask which property the user actually values.

## Selection and recovery

Prefer a short, truthful relationship and tolerable unwanted implications. An obscure definition requiring a lecture fails even if technically accurate. If the source's defining property contradicts the promise, change the world or positioning hypothesis; do not amputate the fact from the ledger. If imagery is strong but tone wrong, change object within the same verified property family.

Use opened specialist definitions or source descriptions, not word associations alone. ## Candidate record and interaction

Use the [session protocol](../../docs/SESSION_PROTOCOL.md) and [source contract](../../docs/SOURCES_AND_RESEARCH.md). Every displayed batch has stable branch/candidate IDs; English spelling; proposed pronunciation/stress where uncertain; exact lineage; separate `form` and `evidence`; source IDs or `none`; useful association and main drawback. Keep intermediate tables in the exploration log or session-owned research notes. Do not put real sessions in this library.

Show two or three contrasting previews before expanding, unless the user already delegated or specified the operation. Ask which property to preserve, not merely which name is “best.” After feedback record the actual words, changed constraints, rejected/parked paths and next options. Praise does not save a name. Add only explicit selections; repeated selection updates the same candidate. A six-name batch is a pause for navigation, never an automatic export.

## Ordered combinations

`lexical-research` → `metaphor-mining` supplies defined properties. `metaphor-mining` → `intact-word-compounding` names the selected image with a familiar partner. `metaphor-mining` → `fragment-blending` compresses sourced imagery with a target concept, retaining both steps.
