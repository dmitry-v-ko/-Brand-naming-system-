## Persistence failure, repair and actual resume

The runner implemented file writes in a small helper to retain checkpoints. It incorrectly interpolated planned future fixture details into state summaries. The actual `cat` read of both T7 files exposed the defect:

- [T02 log](/workspace/naming-review-runs/cycle-01/checkpoints/T02-EXPLORATION_LOG.md) already states T6 delegation and T3/T5 rejected directions, before those turns occurred. T03/T04 summary fields also contain future decisions. Those fields are invalid historical user evidence even though the later fixtures eventually request similar actions.
- [T07 shortlist](/workspace/naming-review-runs/cycle-01/checkpoints/T07-SHORTLIST.md) prematurely includes a planned T8 comment. It also translates the T5 Russian comment rather than preserving the user's exact wording. Neither is permitted by the session contract.
- The original checkpoints were **not rewritten**. The current shortlist was repaired to remove the future comment and restore the actual Russian T5 comment. The log records the failure explicitly. [T07a corrected shortlist](/workspace/naming-review-runs/cycle-01/checkpoints/T07a-corrected-SHORTLIST.md) is a separate checkpoint.
- Both corrected files were read again from disk before T8. The resume helper also independently read them and recorded SHA-256 input hashes in CHECKS.json. Templates were not copied on resume. Only after the T8 fixture actually arrived was its exact comment applied.

This is an observed runner implementation failure, not a missing instruction: the protocol already prohibits inventing earlier feedback and requires exact comments. The writer was informed. A later independent rerun is needed to establish clean temporal persistence; this repaired run cannot supply that evidence.

Other observed limitations: the T5 answer briefly labels the Nevo derivation with its Navo base before giving the new spelling, which is unnecessarily confusing; the final candidate record correctly uses Nevo. Pronunciations remain proposals, especially Nevo and fragment joins. Blend semantic recoverability is weak for manual/clarity tails; no claim of user recognition was made. The run covers only four operators and a small shortlist, so it supplies no evidence for all twelve procedures, voluntary pruning at 20–25 entries, write failure recovery, cross-language accuracy or fictional-source research.
